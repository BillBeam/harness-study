# deepseek-harness 会话日志事件类型地图

读法：本文的范围是本仓库 `study/deepseek-harness/trace/{default,minimal}` 两份会话日志里**实际出现过**的全部 type，共 20 种。每种给出写它的代码位置与一句话说明它记的是什么。所有行号与链接都钉在提交 `cd5ef8148158c3a752a658978873241fdf8e2bbc` 上。需要注意的是，这 20 个 type 并非全是 `SessionEventMap` 里的会话事件：`session` 是 JSONL 文件的头行，`text-chunks` 与 `reasoning-chunks` 是持久化时的打包存储行（它们带 `seq0`/`time0` 而不是 `seq`/`time`），其余 17 种才是经 `Session.append()` 写出的会话事件。

## 一、事件类型

### `agent/inbox/spliced`

记的是 agent 两个待处理消息队列（next-turn / next-step）的一次规范化 splice：在 target 队列的 start 位置删除 `removedCount` 条、插入 `inserted` 里的 UserMessage；删除属于取消行为时带 `outcome: 'canceled'`。

写它的代码位置：[packages/core/agent/src/inbox.ts:178-186](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef8148158c3a752a658978873241fdf8e2bbc/packages/core/agent/src/inbox.ts#L178-L186) —— 178-184 构造 splice 载荷（`removedCount` 为 0、`outcome` 为 undefined 时省略对应键），185 行 validate，186 行 `this.session.append('agent/inbox/spliced', splice)` 是发出点。它位于私有方法 `Inbox.mutate()`：[packages/core/agent/src/inbox.ts:158-193](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef8148158c3a752a658978873241fdf8e2bbc/packages/core/agent/src/inbox.ts#L158-L193)，append 之后 187-191 行才更新内存队列。这是全仓源码唯一写入点；构造函数回放同类事件重建队列在 [packages/core/agent/src/inbox.ts:32-39](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef8148158c3a752a658978873241fdf8e2bbc/packages/core/agent/src/inbox.ts#L32-L39)，类型声明（非发出点）在 [packages/core/agent/src/types.ts:38-44](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef8148158c3a752a658978873241fdf8e2bbc/packages/core/agent/src/types.ts#L38-L44)。

### `assistant/chunk`

记的是模型流式输出的一个原始 chunk（block-start / text-delta / usage / block-end 等），带所属 turn 与 step，逐块原样落盘。

### `reasoning-chunks`
